# 悬浮窗与版本发布记录（2026-11-12）

## 问题与处理

- 原先每个 Agent 只取最新任务，后完成的短命令会覆盖仍在运行的后台长任务，因此看到的是短命令的固定耗时。现在优先取该 Agent 最早启动的活动任务，计时和输出都绑定同一 task ID。
- 列表原先只取最新 500 条，长期任务可能被新历史挤出。现在在 500 条上限内优先保留运行任务，再按时间返回历史。
- 小时级时长增加秒数；任务进入运行状态时立即刷新计时基准。
- 没有活动任务约 10 秒后折叠；悬停预览、移开收起，新任务自动展开。折叠不取消终端任务。
- 悬浮窗以 250 毫秒发现任务、100 毫秒读取运行中任务的增量输出，并在浏览器动画帧中分段写入 xterm；大块输出会平滑追帧，避免一次性贴到底。命令栏也有短暂的输入动画；用户开启减少动态效果时自动关闭动画。该动画仅用于预览，不修改命令、PTY 数据或日志。
- 应用图标改为黑白灰终端符号。悬浮窗状态点和流动提示也使用灰阶，保留运行状态的明暗区别。

## 发布方式

原有 Verify 工作流是三平台的前后端构建和测试，不产出桌面便携包。Release Windows portable 工作流支持推送 `main` 自动递增补丁版本，或由 `v*` 标签触发，检查四处版本一致，运行 Windows 测试、编译 Tauri、打包完整便携目录，再上传 ZIP 和 SHA-256 到 GitHub Release。版本递增以稳定标签为准；尚未发布且高于现有标签的源版本直接采用。构建成功后才原子推送版本提交和标签；并发更新 main 导致非快进推送时会失败，不覆盖他人提交。

标题自动取 `AgentTerminal v版本号`；更新说明使用 GitHub 原生 generated notes，基于 PR、贡献者和提交比较，不使用模型猜测功能。含连字符的版本标记预发布。构建失败不执行发布；非 main 普通分支不发布。没有引入额外插件、外部发布服务或长期令牌，发布作业使用仓库内置 `GITHUB_TOKEN`，需仓库规则允许机器人写入 main 与标签。
